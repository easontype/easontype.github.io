這個站原本是深色科技風：近黑的底、霓虹藍的光暈、mono 字型的導覽列。看起來很「AI」，但有個問題——**沒有人想在那上面讀完一篇三千字的文章**。

所以我把整個站翻掉重做。這篇記錄過程中做的幾個決定，和踩到的雷。

## 為什麼放棄深色

深色介面適合工具，不適合長文。我自己回頭讀舊文章時發現三件事：

- 中文在深底上的筆畫會「發糊」，讀久眼睛累
- 霓虹光暈（`box-shadow` 疊兩層藍）讓每個元素都在搶注意力
- 截圖分享到社群時，深色卡在白色的 timeline 裡像個黑洞

> 設計原則後來收斂成一句話：閱讀面純白，藍只做訊號。

## 關鍵決定：把主色拆成兩層藍

原本的品牌色是 logo 上的亮藍 `#2ea3e6`。改版時發現一個尷尬的事實：這個藍在白底上的對比度只有約 2.6:1，**當文字色直接不及格**（WCAG AA 要求 4.5:1）。

解法是把「一個主色」拆成兩層：

```css
:root {
  /* 可點擊：連結、按鈕、active 狀態（白底對比 5.6:1，過 AA） */
  --primary: #1668b0;

  /* 品牌識別：logo、裝飾節點、hover 底線（永遠不當文字色） */
  --accent: #2ea3e6;
}
```

亮藍退到純裝飾的位置——電路節點、章節標題前的小圓點、導覽 active 的底線。品牌識別還在，可讀性也保住了。

### 電路語彙的降噪版

原本的 logo 是一隻黑底霓虹的電路貓，白底網站沒辦法直接用。與其硬塞，不如把它的「電路語彙」抽出來變成極淡的裝飾線：hero 右上角一組 `#e7f2fb` 描邊的電路 trace，透明度壓到快看不見。知道的人看得出來，不知道的人只覺得乾淨。

## SEO 這次補了哪些洞

改版前這個站的 SEO 只有半套：有 sitemap，但沒有 canonical、沒有 Open Graph 分享卡、沒有結構化資料。這次一次補齊：

1. 每頁 `<link rel="canonical">` 和完整的 OG/Twitter meta
2. 預設 OG 分享圖（1200×630），Threads 貼連結不再是一片空白
3. 首頁 `WebSite` + 文章頁 `BlogPosting` 的 JSON-LD
4. 文章一律英文 slug——中文 slug 分享出去會變成一長串 `%E4%BD%A0` 編碼

短期流量靠社群導流，SEO 是做給半年後的自己收割的。

## 踩到的雷：工具的「假成功」

過程中最詭異的一個坑：改版工具鏈曾經**回報寫檔成功、build 通過、測試全綠——但檔案根本沒落地**。成功訊息是假的。

後來的防範紀律很土但有效：

- 每次寫檔後，用另一個獨立管道回讀確認（`Test-Path`、`git diff`）
- build 完成不看訊息，直接檢查 `dist/` 裡的 HTML 在不在
- 截圖說「通過」不算數，要親眼把圖打開看過

> 教訓：驗證要走和執行不同的通道。同一條通道回報的成功，只是通道自己說自己沒問題。

## 收尾

改版用了一個晚上，其中寫 code 的時間大概只佔一半——另一半在做決定：網域要不要現在買（要）、電子報平台要不要換（不用）、收費功能要不要做（靜態站做不了，走 Gumroad）。

這些決定哪天證明是錯的，再寫一篇。
